# TLS

### 왜 필요할까?
네트워크 통신중에 제 3자가 중간에 확인해서 내용이 유출될 가능성이 있기 때문에 암호화 프로토콜인 TLS를 사용한다.

### SSL 프로토콜? 그것도 보안 아닌가?

맞는데, SSL 프로토콜은 여러 보안 취약점이 있었기 때문에 SSL 3.0 버전이 되었다가, TLS로 대체되었다. \
어떤 취약점이 있었냐 하면 \
대표적으로 POODLE 취약점이 있었는데
- SSL 3.0은 CBC 모드(앞 블록의 암호문을 다음 블록 암호화에 섞어 쓰는 블록 암호 방식)를 사용했는데, 블록 크기를 맞추려고 붙이는 패딩을 검사할 때 **마지막 바이트(패딩 길이)만 확인**했다. (**나머지 패딩 내용은 무시**)
- 게다가 패딩은 MAC(무결성 검사) 범위에도 포함되지 않아서, 조작돼도 알 수 없었다.
- 그래서 Https(SSL 3.0) 프로토콜로 전송시 일부 사용자가 악성 스크립트를 넣어서 통신 과정을 유출할 수 있게 되었다.

TLS는 이걸 어떻게 해결했느냐? 

패딩에 들어가는 모든 바이트의 값이 정해진 규칙과 일치하는지 검사하도록 바뀌었다. 쉽게 말해서, 마지막 바이트만 보고 나머지는 무시하던 SSL 3.0과 다르게 패딩 전체를 검사한다는 것이다. \
TLS 1.0~1.2는 이렇게 CBC 모드를 보완해서 썼고, TLS 1.3에서는 CBC 모드 자체를 없애고 AEAD 방식(AES-GCM 등)만 남겼다.
AEAD는 키로 암호화 해서 대칭키를 가진 사람만 복호화 가능한 기술이다.
