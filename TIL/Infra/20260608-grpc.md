# gRPC?
구글에서 개발된 '오픈소스 고성능 통신 프레임워크'. RPC(원격 함수 호출) 개념을 바탕으로 한다.

### 뭐할때 쓰이나?
보통 MSA(마이크로서비스 아키텍처)처럼 백엔드 서버가 여러 대일 때, 다른 서버에 있는 함수를 본인 서버의 함수인 것처럼 쉽고 빠르게 호출하기 위해 사용한다. (서버 간 내부 통신용)

### 이럴때 쓰면 안된다.

프-백 소통시 거의 표준으로 쓰이는 JSON(텍스트) 대신, 통신 속도를 극대화하기 위해 Protocol Buffers(이진 바이너리 데이터) 형태로 통신한다. 매우 작고 가볍고 빠르지만(REST API 대비 최대 10배), 사람이 눈으로 바로 읽을 수 없어 디버깅이 힘들다. 또한 브라우저 환경에서 직접적인 호출 제약이 있어 프론트엔드-백엔드 소통에는 부적합하다.

### 또 다른 특징
REST API는 HTTP/1.1을 채택한 반면, gRPC는 HTTP/2를 채택했다. 이를 통해 헤더 압축, 멀티플렉싱이 가능하며, 하나의 연결 통로를 뚫어놓고 실시간으로 대량의 데이터를 주고받는 양방향 스트리밍(소켓 방식과 유사)도 지원한다.
